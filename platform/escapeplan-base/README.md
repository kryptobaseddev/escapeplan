# EscapePlan Platform

This repository produces the flashable Raspberry Pi OS image that every EscapePlan appliance boots from. The image is generated with the official [`pi-gen`](https://github.com/RPi-Distro/pi-gen) toolchain and comes pre-configured with the packages, users, services, and bootstrap scripts that the EscapePlan API and web app expect.

## Repository Layout
- `config/` – Base `pi-gen` configuration (`config/config`) plus skip markers for unused upstream stages.
- `stages/stage2/05-escapeplan-base/` – Custom Stage 2 step that installs platform packages, creates the `escapeplan` system user, seeds configuration templates, and wires up systemd units.
- `scripts/` – Automation entrypoints for building, linting, testing, packaging, and health checks.
- `artifacts/` – Generated images, checksums, and manifests (ignored from version control).
- `deploy/`, `work/` – `pi-gen` scratch space (ignored).

## Prerequisites
- Docker or Podman with the ability to run privileged containers (the default build path wraps `pi-gen`’s `build-docker.sh`).
- `git`, `rsync`, `coreutils`, and `shellcheck` on the host that runs the scripts.
- For native (non-container) builds you’ll also need the packages listed in the official `pi-gen` README.

## Building the Image
```bash
pnpm run build:image
```
This command:
1. Clones `pi-gen` (or updates an existing clone) into `work/pi-gen` and checks out tag `2024-07-04-raspios-bookworm-arm64` by default (override via `PIGEN_REF`).
2. Copies EscapePlan config, custom stage files, and stage skip markers into the clone.
3. Runs `pi-gen/build-docker.sh` to produce a Bookworm 64-bit image with SSH enabled and Stage 3–5 skipped.
4. Copies the resulting `.img.xz` into `artifacts/`, emits a SHA-256 checksum, and writes a JSON manifest with metadata.

Environment overrides:
- `PIGEN_REF` – change the upstream tag/commit (e.g., `PIGEN_REF=origin/main`).
- `PIGEN_REPO` – point to a fork of `pi-gen`.
- `ESCAPEPLAN_BASE_VERSION` – stamped into the manifest and image local version suffix.
- `CONTINUE=1` or `PRESERVE_CONTAINER=1` – pass through to `pi-gen` for iterative builds.

## Included Platform Components
The custom Stage 2 step installs and configures:
- Packages: `nodejs` (via NodeSource 22.x), `ffmpeg`, `nginx`, `hostapd`, `dnsmasq`, `avahi-daemon`, `chrony`, `sqlite3`, `jq`, `curl`, `git`, `iptables-persistent`, and supporting utilities.
- System user: `escapeplan` (no login shell) with directories under `/opt/escapeplan`, `/var/lib/escapeplan`, and `/var/log/escapeplan`.
- Templates: `/etc/escapeplan/templates/hostapd.conf.tpl`, `dnsmasq.conf.tpl`, `nginx.conf.tpl`, plus placeholder `api.env`, `web.env`, and FFmpeg configs.
- Systemd units: `escapeplan-platform-init.service` (seeds templates/dirs), `escapeplan-certgen.service` (self-signed bundle for `escapeplan.local`), and disabled unit files for future API/PWA/FFmpeg services.
- TLS bootstrap: first boot generates `/etc/escapeplan/certs/escapeplan.local.{key,crt,pem,pfx}` with SANs for `escapeplan.local` and `10.10.10.1`.

`hostapd`, `dnsmasq`, and `nginx` are installed but deliberately disabled until the operator (via web UI or CLI) writes real configuration derived from the templates.

## Linting & Smoke Tests
```bash
pnpm run lint   # runs shellcheck across scripts and stage assets
pnpm run test   # lint + static + optional guestfish image validation
```
`scripts/check-health.sh` reads the latest build manifest to summarise the most recent image.
`scripts/test-image.sh` performs offline validation of built images using libguestfs (runs automatically when artifacts exist).

## Configuration CLI
`escapeplan-config-apply --config config.json` ingests a JSON payload and renders `/etc/escapeplan/{hostapd,dnsmasq,nginx}.conf`, optional API/Web env vars, and enables/disables systemd units accordingly. This CLI is intended to be called from the EscapePlan admin UI or provisioning service after operators submit real network details.

## Installing EscapePlan Applications
The image ships with systemd unit definitions for:
- `escapeplan-api.service`
- `escapeplan-web.service`
- `escapeplan-ffmpeg@.service`

Each unit includes `ConditionPathExists` guards so they remain inactive until the corresponding application release drops files under `/opt/escapeplan/...` and writes environment files into `/etc/escapeplan/`. The web UI or CLI will be responsible for deploying those assets (e.g., via `.deb` package generated by `scripts/package-deb.sh`).

## Packaging Releases
```bash
scripts/package-deb.sh --version 0.1.0 --api-dir ../apps/escapeplan-api/dist --web-dir ../apps/escapeplan-web/build 
```
The script assembles `/opt/escapeplan/{api,web,ffmpeg}` payloads into `artifacts/<package>_<version>_arm64.deb`, writes maintainer scripts that reload systemd, and ensures ownership is set to the `escapeplan` user. Provide prebuilt artifacts from the application repos before running it.

## Integration Testing
`scripts/test-image.sh <image>` mounts a generated `.img` using libguestfs and verifies key files, templates, and unit definitions exist. `pnpm run test` will run this automatically when artifacts are present and `guestfish` is installed.
`scripts/test-hardware.sh` runs remote checks against a Pi when `ESCAPEPLAN_PI_HOST` is set (requires passwordless SSH) to confirm systemd services and wlan0 status.
